# 机器人菜单配置系统 - 技术设计文档

## 一、系统概述

### 1.1 业务需求
实现多级权限控制的机器人菜单管理系统，支持运营端和代理端的分级管理。

### 1.2 核心功能
- 运营端：最高权限，可强制禁用菜单
- 代理端：次级权限，可自由启用/禁用菜单（受运营端限制）
- 支持拖拽排序、跨区域移动
- 批量保存机制

## 二、数据库设计

### 2.1 表结构

```sql
CREATE TABLE `bot_menu` (
  -- 主键
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '菜单ID',
  
  -- 关联字段
  `agent_id` BIGINT UNSIGNED NOT NULL COMMENT '代理ID',
  `bot_id` BIGINT UNSIGNED DEFAULT NULL COMMENT '机器人ID（可选）',
  
  -- 基本信息
  `menu_name` VARCHAR(100) NOT NULL COMMENT '菜单名称',
  `menu_type` TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '菜单类型: 1=菜单按钮 2=内联按钮',
  
  -- 双状态控制（核心字段）
  `admin_status` TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '运营端状态: 1=允许使用 2=强制禁用',
  `agent_status` TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '代理端状态: 1=启用 2=禁用',
  `display_order` INT NOT NULL DEFAULT 0 COMMENT '显示顺序（启用菜单专用，越小越靠前）',
  
  -- 功能配置
  `inner_type` VARCHAR(20) DEFAULT NULL COMMENT '内联类型: url=链接 callback=回调',
  `inner_value` TEXT DEFAULT NULL COMMENT '内联值: URL地址或回调数据',
  `callback_type` VARCHAR(50) DEFAULT NULL COMMENT '回调类型标识',
  
  -- 扩展字段
  `create_type` TINYINT UNSIGNED DEFAULT 1 COMMENT '创建类型: 1=手动创建 2=系统创建',
  `other` TEXT DEFAULT NULL COMMENT '其他扩展信息（JSON格式）',
  
  -- 时间戳
  `created_at` BIGINT UNSIGNED NOT NULL COMMENT '创建时间（Unix时间戳，秒）',
  `updated_at` BIGINT UNSIGNED NOT NULL COMMENT '更新时间（Unix时间戳，秒）',
  
  -- 索引
  PRIMARY KEY (`id`),
  INDEX `idx_agent_status` (`agent_id`, `admin_status`, `agent_status`),
  INDEX `idx_display_order` (`agent_id`, `admin_status`, `agent_status`, `display_order`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='机器人菜单配置表';
```

### 2.2 核心字段说明

| 字段 | 类型 | 说明 | 可选值 | 修改权限 |
|------|------|------|--------|----------|
| `admin_status` | TINYINT | 运营端控制状态 | 1=允许使用<br>2=强制禁用 | 仅运营端 |
| `agent_status` | TINYINT | 代理端控制状态 | 1=启用<br>2=禁用 | 代理端 |
| `display_order` | INT | 显示顺序 | 0, 1, 2, 3... | 代理端 |

## 三、权限控制逻辑

### 3.1 状态组合表

| admin_status | agent_status | 最终显示 | 代理操作权限 | 说明 |
|--------------|--------------|----------|-------------|------|
| 1（允许） | 1（启用） | ✅ 显示 | 可拖拽、可禁用 | 正常启用 |
| 1（允许） | 2（禁用） | ❌ 不显示 | 可启用 | 代理自己禁用 |
| 2（强制禁用） | 1（启用） | ❌ 不显示 | 🔒 不可操作 | 运营强制禁用 |
| 2（强制禁用） | 2（禁用） | ❌ 不显示 | 🔒 不可操作 | 运营强制禁用 |

### 3.2 判断公式

```javascript
// 最终是否显示
const isVisible = (menu) => {
  return menu.admin_status === 1 && menu.agent_status === 1
}

// 代理端是否可以操作
const canAgentControl = (menu) => {
  return menu.admin_status === 1
}
```

## 四、前端实现

### 4.1 TypeScript 类型定义

```typescript
/**
 * 运营端状态枚举
 */
export enum AdminStatus {
  ALLOWED = 1,        // 允许使用
  FORCE_DISABLED = 2  // 强制禁用
}

/**
 * 代理端状态枚举
 */
export enum AgentStatus {
  ENABLED = 1,   // 启用
  DISABLED = 2   // 禁用
}

/**
 * 菜单项完整类型
 */
export interface BotMenuItem {
  id: number
  agent_id: number
  bot_id?: number | null
  menu_name: string
  menu_type: 1 | 2
  admin_status: AdminStatus
  agent_status: AgentStatus
  display_order: number
  inner_type?: 'url' | 'callback' | null
  inner_value?: string | null
  callback_type?: string | null
  create_type?: 1 | 2
  other?: string | null
  created_at: number
  updated_at: number
}
```

### 4.2 代理端界面功能

**启用区域**
- 显示条件：`admin_status=1 && agent_status=1`
- 支持拖拽排序（更新 `display_order`）
- 可拖到禁用区域（更新 `agent_status=2`）

**禁用区域**
- 普通禁用：`admin_status=1 && agent_status=2`（可拖回启用）
- 运营禁用：`admin_status=2`（灰色锁定，显示🔒图标，不可操作）

### 4.3 交互规则

| 操作 | 条件 | 结果 |
|------|------|------|
| 启用区域内拖拽排序 | `admin_status=1` | 交换 `display_order` |
| 启用 → 禁用 | `admin_status=1` | 更新 `agent_status=2` |
| 禁用 → 启用 | `admin_status=1` | 更新 `agent_status=1` |
| 操作运营禁用的菜单 | `admin_status=2` | ❌ 阻止操作，提示"该菜单已被运营端禁用" |

### 4.4 保存机制

1. 所有拖拽操作只更新本地状态（`keyboardLayout`, `disabledMenus`）
2. 点击"保存配置"按钮才调用API
3. 保存时重新计算 `display_order`：第一个位置=0，第二个=1，依此类推
4. 批量更新所有菜单的 `agent_status` 和 `display_order`

## 五、API 接口设计

### 5.1 代理端 - 批量更新接口

**接口地址**
```
POST /v1/bot/menu/batch-update
```

**请求参数**
```typescript
interface AgentBatchUpdateRequest {
  enabled_menus: {
    id: number
    display_order: number
  }[]
  disabled_menu_ids: number[]
}
```

**请求示例**
```json
{
  "enabled_menus": [
    { "id": 5, "display_order": 0 },
    { "id": 2, "display_order": 1 },
    { "id": 8, "display_order": 2 }
  ],
  "disabled_menu_ids": [3, 6, 9]
}
```

**后端处理逻辑**
```python
def agent_batch_update(request, agent_id):
    # 1. 验证权限：只能更新 admin_status=1 的菜单
    menu_ids = [m.id for m in request.enabled_menus] + request.disabled_menu_ids
    menus = db.query(
        "SELECT id, admin_status FROM bot_menu WHERE id IN (?) AND agent_id=?",
        [menu_ids, agent_id]
    )
    
    # 2. 检查是否有运营禁用的菜单
    for menu in menus:
        if menu.admin_status == 2:
            return {"error": f"菜单 {menu.id} 已被运营端禁用，无法操作"}
    
    # 3. 更新启用菜单
    for menu in request.enabled_menus:
        db.execute(
            "UPDATE bot_menu SET agent_status=1, display_order=? WHERE id=? AND agent_id=?",
            [menu.display_order, menu.id, agent_id]
        )
    
    # 4. 批量禁用菜单
    if request.disabled_menu_ids:
        db.execute(
            "UPDATE bot_menu SET agent_status=2 WHERE id IN (?) AND agent_id=?",
            [request.disabled_menu_ids, agent_id]
        )
    
    return {"success": True}
```

**响应示例**
```json
{
  "code": 0,
  "message": "success",
  "data": null
}
```

### 5.2 运营端 - 强制控制接口

**接口地址**
```
POST /v2/bot/menu/admin-control
```

**请求参数**
```typescript
interface AdminControlRequest {
  menu_id: number
  admin_status: 1 | 2  // 1=允许 2=强制禁用
}
```

**请求示例**
```json
{
  "menu_id": 5,
  "admin_status": 2
}
```

**后端处理逻辑**
```python
def admin_control_menu(request):
    # 更新运营端状态
    db.execute(
        "UPDATE bot_menu SET admin_status=? WHERE id=?",
        [request.admin_status, request.menu_id]
    )
    
    # 如果是强制禁用，同时更新所有代理的状态（可选）
    if request.admin_status == 2:
        db.execute(
            "UPDATE bot_menu SET agent_status=2 WHERE id=?",
            [request.menu_id]
        )
    
    return {"success": True}
```

## 八、关键设计点

### 8.1 双状态分离
- `admin_status`：运营端控制，最高优先级
- `agent_status`：代理端控制，受运营端限制
- 两个状态独立存储，互不干扰

### 8.2 display_order 设计
- 使用递增整数（0, 1, 2, 3...）
- 越小越靠前（符合直觉）
- 只对启用菜单有意义
- 禁用菜单的 `display_order` 可设为 0

### 8.3 批量更新优化
- 一次请求完成所有更改
- 减少网络开销
- 保证数据一致性（事务处理）

### 8.4 权限验证
- 后端强制检查 `admin_status`
- 防止代理越权操作
- 前端UI锁定提示

### 8.5 用户体验
- 拖拽排序直观易用
- 运营禁用的菜单显示🔒图标
- 操作锁定菜单时显示提示信息

---

## 九、优势总结

1. **权限清晰**：运营最高权限，代理受限权限，层级分明
2. **性能优化**：批量更新，减少网络请求，提升响应速度
3. **用户体验**：拖拽排序，直观易用，操作流畅
4. **安全可靠**：后端验证，防止越权操作，数据安全
5. **扩展性强**：支持未来添加更多控制维度和功能

---

## 十、注意事项

1. 前端必须验证 `admin_status` 后才允许拖拽操作
2. 后端必须在更新前验证 `admin_status=1`
3. `display_order` 在保存时重新计算，避免重复和混乱
4. 运营端禁用菜单时，建议同时更新所有代理的 `agent_status=2`
5. 索引设计要考虑查询性能，特别是 `display_order` 排序
